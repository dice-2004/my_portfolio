## 1. プロジェクトの背景・概要
* **目的**: ユーザー (Dice) の作品や経歴を紹介する、モダンで実戦的なポートフォリオサイトの構築。
* **運用環境**: 自宅にある N100 Mini PC（リソース制限あり） ＋ Cloudflare Tunnel を用いたセキュアな公開。
* **開発プロセス**: 今回、ユーザーはGoやNext.jsの初学者であるため**【問題・レビュー駆動の学習モード】** を採用する。AIはいきなり完成形の全コードを提示するのではなく、「どこにどのようなコードを書くべきか」をヒント付きの問題形式でガイドし、ユーザーが実装を終えたらレビューや答え合わせを行う「ペアプログラミング・教育的アプローチ」を取る。また作業ログ（CHANGELOG.md）には、ただの変更履歴だけでなく、**ユーザーからの鋭い指摘、発生したエラーの現象とその解決経緯、コードの修正点**をAIが事細かに記録していく。

## 2. コアとなる技術スタック
* **バックエンド**: Go (Gin)
  * 選定理由: N100での軽快なスループット、`net/http` 互換、豊富なミドルウェア。
* **フロントエンド**: Next.js, React, TypeScript
* **スタイリング**: Tailwind CSS + Shadcn UI + Framer Motion (Glassmorphism などのモダンな表現)
* **データベース**: SQLite (単一ファイルで自宅PCでのバックアップ・運用が容易)
* **インフラ**: Docker (docker-compose) による一括管理

## 3. 設計レビューで決定した「重要な仕様変更」の経緯
当初の案から、技術面接官の視点も交えた辛口レビューを経て、以下の実戦的な要件へと昇華・決定した。

1. **AR/XR機能の洗練**:
   * 当初予定していた「サイコロが転がる」演出を廃止。
   * **Glassmorphism** と空間にテキスト・パネルが浮遊するモダンな表現へシフト。
   * iOS Safariなど非対応ブラウザへのフォールバック（WebGLモードや対応予定ツールチップ）を明記。
2. **認証システム (Ed25519)**:
   * 業界標準のWebAuthn等ではなく、**学習の一環としてEd25519の公開鍵認証を自前実装**。
   * **ファイルインポート方式**を採用：秘密鍵をブラウザに保存せず、ログインのたびに `.pem` ファイルを読み込ませる（Web Crypto API使用）ことで漏洩リスクをゼロにする。
3. **コンテンツ管理とリソース保護**:
   * 当初の Discord / Notion 連携を廃止。
   * 代わりに **Web Markdown Editor** を独自実装。左右分割のリアルタイムプレビューを搭載。
   * N100のリソース枯渇を防ぐため、画像アップロードは「サイズ上限2MB」「拡張子制限（jpg, png, webp）」を設ける。
4. **セキュリティ・耐障害性**:
   * **XSS保護**: フロント（DOMPurify）とバックエンド（bluemonday）の両面でタグを無害化。
   * **DDoS保護**: Ginミドルウェアによる Rate Limit を導入。
   * **バックアップ戦略**: GitHub Actions を用いて SQLite の `.db` ファイルと画像を日次でバックアップ（S3/R2等へ保存）。
